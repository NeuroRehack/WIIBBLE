Technical Reference

WIIBBLE — Data Processing Pipeline

From raw HID bytes off the Wii Balance Board to Centre of Pressure in centimetres and posturographic feature extraction.

▶

Pipeline Overview

Seven stages from hardware to features

1 · Raw HID Read

32 bytes read from the board each frame via read_data(device). ~75–100 Hz, non-uniform intervals.

2 · Parse & Tare

Bytes decoded to kg per corner via parse_data(). Baseline (tare) subtracted; scaled by SCALE_FACTOR.

3a · Force Deviation (Recording path — raw)

Net ML and AP forces computed from raw_corners via calculate_force_deviation_kg(). Written to CSV — never filtered.

3b · Moving Average Filter (Display path only)

Window of N frames smoothed via apply_filter(). Only affects the live cursor — has no effect on recorded data.

4 · CoP Conversion

Force deviations converted to Centre of Pressure in centimetres using the WBB geometry (Leach et al. 2014, Eq. 1). ML and AP coordinates independently.

5 · SWARII Resampling → 25 Hz

Non-uniform timestamps resampled to a uniform 25 Hz grid using the Sliding Window Weighted Averaged Interpolation algorithm.

6 · Butterworth Filter (0–10 Hz, order 4)

Zero-phase bandpass applied by the Stabilogram class. Removes drift (<0 Hz) and high-frequency noise (>10 Hz) from the CoP signal.

7 · Feature Extraction (~80–90 features)

Posturographic descriptors computed by compute_all_features(). Saved alongside the CSV as features_YYYYMMDD_HHMMSS.json.

1

HID Data Acquisition

read_data(device) · data_processing.py

32-byte HID report

Each frame the board transmits a 32-byte Human Interface Device (HID) report. Only bytes at fixed offsets correspond to sensor data — the rest are status or padding bytes.

CornerInteger byte indexFractional byte index
Top-rightdata[3]data[4]
Bottom-rightdata[5]data[6]
Top-leftdata[7]data[8]
Bottom-leftdata[9]data[10]

Each corner uses two bytes: the first carries the integer part and the second carries the fractional part scaled over 255 (i.e. it is an 8-bit fixed-point fraction).

2

Parse & Tare Correction

parse_data() · data_processing.py

Raw byte → kg per corner

The two bytes for each corner are combined into a single dimensionless raw value, then scaled to kilograms using an empirically derived calibration constant and baseline-subtracted.

$$F_{\text{corner}} \; [\text{kg}] \;=\; \Bigl(\underbrace{B_i}_{\text{integer byte}} + \underbrace{\frac{B_{i+1}}{255}}_{\text{fractional byte}} \;-\; T_{\text{corner}}\Bigr) \;\times\; K$$

Where:

SymbolMeaningValue / Source
$B_i$Integer HID byte for the cornerRuntime
$B_{i+1}$Fractional HID byte (÷ 255)Runtime
$T_{\text{corner}}$Tare offset (empty-board average over 10 readings)Measured on startup
$K$SCALE_FACTOR — empirical kg/raw-unit calibration2.6441910

This yields four independent force measurements $F_{TL},\, F_{TR},\, F_{BL},\, F_{BR}$ (top-left, top-right, bottom-left, bottom-right) each in kilograms.

4

Force Deviations

calculate_force_deviation_kg() · data_processing.py

Net mediolateral and anteroposterior forces

The four corner forces are combined into two net force deviation values — one per axis. These are the quantities recorded to CSV and later used for CoP conversion.

Mediolateral (x)

$$x_{\text{kg}} = (F_{TR} + F_{BR}) - (F_{TL} + F_{BL})$$

Positive $x$ = weight shifted right. Negative $x$ = weight shifted left.

Anteroposterior (y)

$$y_{\text{kg}} = (F_{TL} + F_{TR}) - (F_{BL} + F_{BR})$$

Positive $y$ = weight shifted forward. Negative $y$ = weight shifted backward.

The total body weight used for normalisation is captured independently during the calibration phase:

$$W_{\text{total}} = F_{TL} + F_{TR} + F_{BL} + F_{BR}$$
5

Centre of Pressure Conversion

to_cop_array() · analysis.py · Leach et al. 2014, Eq. 1

CoP Formula — Leach et al. (2014), citing Winter (2004)
$$\text{CoP}_{ML}\;[\text{cm}] \;=\; d_{ML} \;\times\; \frac{x_{\text{kg}}}{W_{\text{total}}}$$ $$\text{CoP}_{AP}\;[\text{cm}] \;=\; d_{AP} \;\times\; \frac{y_{\text{kg}}}{W_{\text{total}}}$$

Derivation

This formula follows directly from the rigid lever arm model of a four-point force platform. Assuming each sensor pair acts as a fulcrum at distance $d$ from the geometric centre:

$$\text{CoP}_{ML} = \frac{d_{ML} \cdot (F_{TR} + F_{BR}) \;-\; d_{ML} \cdot (F_{TL} + F_{BL})}{F_{TL} + F_{TR} + F_{BL} + F_{BR}}$$

Since $d_{ML}$ is constant, it factors out of the numerator:

$$= d_{ML} \;\cdot\; \frac{(F_{TR} + F_{BR}) - (F_{TL} + F_{BL})}{W_{\text{total}}} \;=\; d_{ML} \;\cdot\; \frac{x_{\text{kg}}}{W_{\text{total}}}$$

The same derivation applies to the AP axis using $d_{AP}$ and $y_{\text{kg}}$. The result is expressed in centimetres because $d_{ML}$ and $d_{AP}$ are in centimetres.

ConstantValueSource
$d_{ML}$21.65 cmLeach et al. 2014, Fig. 3: $X = 433\,\text{mm},\ d = X/2$
$d_{AP}$11.9 cmLeach et al. 2014, Fig. 3: $Y = 238\,\text{mm},\ d = Y/2$
⚠

The recorded CSV always contains raw, unfiltered $(x_{\text{kg}},\, y_{\text{kg}})$ values. The display cursor moving-average filter is applied only to the live visualisation and has no effect on the data used for CoP conversion. The ui_filter_window metadata comment in the CSV is provenance only.

6

SWARII Resampling & Butterworth Filter

Stabilogram.from_array() · code_descriptors_postural_control

SWARII — 25 Hz uniform grid

WBB sampling is non-uniform (~75–100 Hz with jitter). The Sliding Window Weighted Averaged Interpolation (SWARII) algorithm produces a uniform 25 Hz time series without introducing the interpolation artefacts of simple linear resampling.

The 25 Hz target is sufficient to capture all clinically relevant postural sway frequencies (0–10 Hz, practically 0–3 Hz).

Butterworth Bandpass

A zero-phase 4th-order Butterworth filter is applied after resampling:

$$0\,\text{Hz} \;\leq\; f \;\leq\; 10\,\text{Hz}$$

Zero-phase (forward + backward pass via filtfilt) ensures no temporal shift is introduced. The lower cut removes slow drift artefacts; the upper cut removes high-frequency noise above the sway band.

7

Feature Extraction

compute_all_features() · ~80–90 posturographic descriptors

Feature families

FamilyExamplesClinical relevance
Positional Mean displacement, RMS, 95% ellipse area, sway range Overall sway magnitude; asymmetry detection
Dynamic Mean velocity, path length, mean speed Neuromuscular response speed; fatigue
Frequentist Mean frequency, 95% power frequency, PSD peak Shift toward higher frequencies indicates pathology
Stochastic (SDA) Hurst exponent, short/long-interval scaling, critical time Open vs. closed loop control boundary (Winter 1996)

Results are written to features_YYYYMMDD_HHMMSS.json alongside the corresponding CSV in the configured recordings folder (Save Location in settings; default ~/Documents/WIIBBLE/recordings). Run wiibble-process-recordings --new offline after a session; recordings shorter than 20 seconds are skipped.

Implementation Reference

Key functions and where to find them

# 1. Parse raw HID bytes to corner kg values
corners = parse_data(data, data_struct)          # data_processing.py

# 2. Store raw values before any filtering (for recording)
app_state.raw_corners = corners

# 3. Apply moving average (display only)
smoothed = apply_filter(corners, filter_buffer, ui_filter_window)

# ── In analysis.py (offline, after recording ends) ──────────────────────

# 4. Load CSV and parse metadata
data, metadata = load_recording(path)            # → (N,3): time_s, x_kg, y_kg

# 5. Convert force deviations to CoP in cm  (Leach 2014, Eq.1)
cop = to_cop_array(data, total_weight_kg)        # → (N,3): time_s, ML_cm, AP_cm
#  ML_cm = 21.65 × x_kg / W_total
#  AP_cm = 11.90 × y_kg / W_total

# 6. SWARII → 25 Hz + Butterworth 0–10 Hz (inside Stabilogram)
stab = Stabilogram()
stab.from_array(cop)

# 7. Extract ~80–90 posturographic features
features = compute_all_features(stab)            # → dict
